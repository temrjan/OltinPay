# План: чистка сервера 7demo — по этапам

Дата: 2026-07-27 · Инженер (спека) · Ревьюер снял read-only инвентарь 2026-07-26.
Периметр ШИРЕ OltinPay: сервер общий, продукты разных владельцев. Двойной Гейт-1/Гейт-2.
Диск не в кризисе (67%, 33G свободно) → **спешить некуда, по одному пункту с ратификацией.**

## Инварианты всего плана (действуют на КАЖДОМ этапе)
- **Уровень-3 карантин — НЕ ТРОГАТЬ ни при каком «0 контейнеров = мёртвое»:**
  - `infra_pg_data / infra_qdrant_data / infra_redis_data` — общие БД 5+ продуктов
    (aiprikorm_db, oltinpay_db, dorify_v2_db, znai_lite, sulum_db). Чистить продукт =
    удалять КОНКРETНУЮ БД внутри, НЕ том/контейнер инфры.
  - `oltinchain-oltinpay-{api,webapp}` + `*:pre-cutover-2026-07-22` — откатные образы R-4,
    под запретом **до R-5**.
  - Сети `internal`, `proxy` — магистраль Caddy-роутинга, не «неиспользуемые».
  - `caddy:2-alpine` — единственный реверс-прокси; расхождение «4/1 контейнер» разобрать
    ЧТЕНИЕМ отдельно, не удалять вслепую.
- **`docker image prune -a` ЗАПРЕЩЁН** (снесёт oltinchain-откатные) — оговорка не должна
  раствориться в «почистим всё». Только адресное удаление по имени.
- **Порядок эскалации (каждый следующий необратимее):** `stop` → наблюдение → `rm`
  контейнера → `rm` образа → **и только потом** volume/БД.
- **Снимок-страховка перед КАЖДЫМ томом с данными** (паттерн `/home/aiwell/backups/…`,
  как для oltinchain). Тома необратимы.
- **По одному пункту:** удалил → перечитал состояние → следующий. Не пакетом.

## Этап 0 — предпосылки (ГЕЙТ перед стартом, решения Капитана)
Без них Этапы 1–3 не начинаются:
1. **Матрица владения** — по каждому продукту: ТВОЁ / КЛИЕНТСКОЕ / ОБЩЕЕ.
   Незакрытые: `dorify`, `aqllify`, `aiprikorm`, `sulum`, `latent`, `ledger-ai`,
   `openclaw`, `product-znai`. **Клиентское и неоднозначное — не трогаем вообще.**
2. **Тайминг** — чистим сейчас или откладываем (диск свободен, стоимость отсрочки = 0).
3. Подтвердить снапшот-каталог и что Уровень-3 заморожен в этой спеке.

Каждый пункт: Гейт-2 Ревьюера → ратификация → удаление → перечитывание.

## Этап 2 — Уровень 2 (данные, ТОЛЬКО по-штучно, со снимком; только ТВОЁ)
Похоже на сирот, но необратимо. Снимок перед каждым томом.
- `znai-cloud_znai_{pgdata,qdrant,redis}` (тома) — хвост СТАРОЙ топологии до переезда на
  `znai_lite`/shared. Риск: неполная миграция (часть истории только в старом qdrant).
- `rustok-wallet` (том) — по памяти `rustok-wallet:v0.5*` удалены 11.07; подтвердить, что
  это тот хвост.
- `server_{pg_data,redis_data,uptime-kuma-data}` (тома) — до-переименования (uptime-kuma
  теперь под `monitoring`); имя слишком общее — подтвердить.
- `product-znai-*`, `znai-cloud-app`, `znai-cloud-znai-cloud` (образы) — вероятно
  переименование `znai-cloud → product-znai`; сверить, какой реально деплоится.
